# README_AGENT.md — AI 协作者契约文档

> **本文档的读者是大语言模型 / 编码 Agent,不是人类。** 人类请阅读 [README.md](README.md) / [README_ZH.md](README_ZH.md)。
>
> 你(Agent)即将在一个**内核态修改框架**项目上工作。这不是普通的应用开发:
> 核心载荷是一个 KernelPatch Module(KPM)——它在内核空间运行,持有跨进程内存读写与
> syscall 拦截能力。一个错误的 sleep、一次错误上下文里的分配、一个越界的内存写,
> 都会直接 panic 内核或损坏任意进程的内存——**手机变砖 / 开机循环是真实的失败模式**。
> 同时,本项目的核心价值是一条安全性质:"目标进程内零驻留"——破坏它比崩溃更糟,
> 因为它静默且难以察觉。
>
> 本文档包含三类知识:
> 1. **红线铁律**(§2):惯性思维最想"优化"但绝对不能碰的代码模式,每条附违例后果;
> 2. **架构与目标状态**(§4-§7):快速建立正确的系统心智模型与 Native API 分类学;
> 3. **验证协议**(§8):改完之后如何证明没有破坏系统。

## 1. 项目本质(30 秒版)

**KePosed = Android ARM64 内核级修改框架。单个 KPM(`keposed.kpm`)对外暴露窄原语集(跨进程内存读写/搜索、syscall 结果塑形、进程事件、方法级 hook),通道 = **文件描述符句柄制**(开机一次 syscall 握手后,内核分发匿名 fd;此后所有通信走标准内核文件接口,句柄本身即凭证,逐句柄烙印能力位+作用域);调用方是以 nobody 身份运行的用户态二进制模块;root 守护进程 `keposedd` 只管控制面。设计目标:目标进程内零驻留代码——只有被明确修改的数据不同。**

**数据面/控制面分工(2026-11-09 owner 确认口径,防漂移)**:**数据面(内存读写、扫描、hook、监听、一切热路径原语) = 模块 ↔ 内核直连,ioctl 直达,守护进程不在环里**——速度零损耗、daemon 负担为零、崩溃不传染(句柄生命周期绑模块进程的 fd,daemon 死活不影响运行中的模块)。守护进程职责收窄为控制面管理:①安装时铸句柄并经 SCM_RIGHTS 递进(一次性冷路径,root 承重墙:nobody 不得自铸);②事件拉起模块(RL-20 无常驻的必然代价,每事件一次 clone+exec,非每操作一次;clone 旗标 = pidns/mountns 隔离 + netns 按开关,RL-07b);③模块管理(联网开关 netns 断网 RL-07a、卸载/强杀);④注册表持久化重放 + WebUI(冷路径)。联网开启时模块直连网络不经 daemon(RL-07a),联网关闭为控制面动作。**禁止任何"为了方便"把热路径原语改成经 daemon 中转的设计——那是反解耦**。

核心事实:

| 事实 | 含义 |

| KPM 形态,非 .ko、非 app | 以 KernelPatch Module 运行于内核空间;加载交给宿主加载器 |

| 通道 = 句柄制(裁决,2026-11-08 二次定稿) | 开机握手(一次 syscall,带魔法数)→ 内核分发 anon fd;模块句柄由守护进程经 fd 传递(SCM)递给模块进程;之后全部通信走 read/write/ioctl 标准接口。句柄即凭证:不可猜(内核记账)、不可偷(仅持有者可用)、进程死自动失效(内核 close 回调)。先例:KSU 2025-11 起(reboot syscall 一次性握手 → anon_inode fd,此后全走 ioctl) |
| 方法级 hook 进 v1(裁决,2026-11-08 深夜定稿;2026-11-09 第二轮重构) | **终局形态一次性实现**(不分期):影子页双视图 + 读透明 + **整模块映像跳板**(2026-11-09 重构:映像 = 模块自己的内存,注册时驱动订页,窗口期驱动让目标线程"用上"——具体手段未锁死,验收线 = 目标永不可见)。原"方法级 hook 明确不做"裁决被推翻——非 LSPosed 式实现不违反零注入(§6.8)。一次性到位的理由:地基(异常入口/页表手术/ART 定位)是共用的一次性工程,分期=中间形态重做;将来更好方案只替换跳板策略,地基不动。**v1 完全体 = T0 静态规则 + T2 映像跳板**(两形态平权,见 §6.8) |

## 2. 红线铁律(RED LINES — 绝对禁止清单)

每条格式:**规则 / 为什么 / [违例后果]**。编号 RL-xx 供引用。

### A. 零注入纪律(项目存在的理由)

- **RL-01** 永不向目标进程映射任何**新驻留**代码——不注入 dex/ELF、不写常驻
  shellcode、不改 ArtMethod entrypoint、不远程线程。内核写目标进程内存时,
  **写入的数据必须是数据**(数值、字段、结构体内容),永远不是可执行载荷。
  (2026-11-08 深夜修订)方法级 hook **解禁**,但唯一合法形态 = 影子页双视图
  (§6.8):原页字节永不改动(校验/扫描/读恒见原样),hook 执行体只存在于
  窗口期临时视图或经整模块映像执行的模块回调——**瞬时代码存在 ≠ 驻留代码存在**,
  零驻留不变式(§6.4 观测纯度)依然成立。LSPosed 式(改 entrypoint/常驻跳板)
  仍然禁止。
  `[一旦驻留,目标进程内出现可扫描的代码痕迹——项目从"无物可扫"退化为"藏猫猫",核心卖点死亡。影子页是"执行时才存在"的视图,不落此列;但任何让代码过夜的设计都落此列]`

- **RL-02** 目标进程的 maps/fd/threads 列表必须保持原生。不为目标进程创建 fd(不 dup、
  不 SCM_RIGHTS)、不创建线程、不改 VMA 属性。数据修改只在既有页内发生。
  `[新增 fd/线程/VMA 本身就是可检测痕迹,与 RL-01 同级]`

### B. 内核上下文纪律(错误 = panic/砖)

- **RL-03** syscall hook 的 `before`/`after` 回调内**绝不**睡眠/阻塞/获取可能被占的锁/
  `kmalloc(GFP_KERNEL)`。回调运行在 syscall 路径上,被中断的线程可能持有任意锁。
  需要分配的状态一律在 `KPM_INIT` 或命令安装时预分配;确需延迟处理走 workqueue。
  `[死锁/优先级反转/原子上下文睡眠 panic]`

- **RL-04** gateway 分发路径(私有 syscall 的处理函数)与 hook 回调内**绝不**直接
  `printk` 洪水、绝不浮点运算。日志一律限流(同 (op,target) 计数 + 周期采样)。
  `[观测体系自身成为放大器;ARM64 内核态 FP 需显式保存恢复]`

- **RL-04a** 逐命令目标作用域强制(2026-11-08 裁决;2026-11-09 目标标识器扩展):
  每条作用于目标进程的命令,在能力检查之后、执行之前**必须**核对"目标进程在调用
  模块的作用域清单内"。作用域条目 = **包名或可执行文件路径**两种形态(2026-11-09
  owner 裁决:新增原生二进制目标——用户在 WebUI 自选具体二进制路径;直接运行
  的可执行文件无包名,以路径标识)。守护进程存标识器(包名/路径),事件到达时
  换算 uid/exe(多用户/分身同包名全覆盖,照抄 LSPosed)。作用域清单是用户在
  WebUI 勾选的(含 system_server/android 项与二进制路径项,推荐作用域预勾、
  静态作用域支持),模块自身声明无效。**无特权护栏、无实验性标志**(owner 裁决:
  目标选择是用户的自由;原生目标比 app 更简单,不配实验性;hook 哪里是模块
  开发者的事)。
  `[无作用域强制 = 装一个模块等于给它的作用域全集发了 root 级读写券——授权模型空谈]`

- **RL-05** 跨进程内存写遇到只读目标页时,必须走 `mm/` 内统一的页表遍历路径
  (改 PTE 临时可写 → 写 → 恢复 → flush),该实现只允许存在一份。绝不内联第二份拷贝。
  `[两份实现 = 两处会漂移的页表语义;漏恢复 = 目标进程拿到永久可写 .text = 可检测痕迹 + 数据竞态]`

- **RL-06** 所有 hook(syscall hook、inline hook)**必须**在 `KPM_EXIT` 里对称卸载;
  所有内核分配**必须**对称释放。卸载路径与安装路径同一次提交内完成、同一次评审。
  `[KPM 被卸载后残留 hook = 跳转到已释放内存 = 内核 panic;boot 时加载的 KPM 卸载失败 = 每次开机泄漏]`

### C. 信任模型纪律(模块永远摸不到 root)

- **RL-07** 模块进程**永不**以 root/shell/manager uid 运行,固定以 **nobody(9999)** 运行
  (2026-11-08 裁决;曾议 shell/自定义 9000 段均否决——shell 权限过高,自定义 uid 可被
  app 通过用户管理服务枚举,是自挂牌)。spawn 流程固定:
  校验 manifest → 内核铸造模块句柄(烙印能力位+作用域)→ clone(CLONE_NEWPID 与
  CLONE_NEWNS;net=off 时加 CLONE_NEWNET,RL-07a)→ 子进程内 mountns 轻监狱
  (重挂 /proc + 模块树 tmpfs 影子 + 仅回绑自身目录,RL-07b)→ setgroups/setgid/setuid 9999
  → prctl(PR_SET_NO_NEW_PRIVS) → exec,**句柄经 fd 传递(SCM_RIGHTS)从守护进程递进子
  进程**——绝不经 argv/环境变量。setgroups 清单与联网开关联动(P7):net=on ⇒ 含
  AID_INET(3003),net=off ⇒ 空表。模块数据目录由守护进程在安装时预建(nobody 可写;
  回绑真实目录,写入落真实存储)。
  任何"这个模块比较特殊,给它 root 方便调试"的想法都拒绝——调试用 gateway 的调试命令
  + daemon 侧日志。
  `[模块拿到 root = 信任模型崩塌;nobody 身份是作用域强制的物理前提——模块自己碰不了任何 app,正门是唯一通路,RL-04a 才查得住。这是本框架与"脚本合集"的分界线]`

- **RL-07a** 模块联网 = 布尔开关 + netns 出生制断网(2026-11-09 定稿并当日修订,
  **废除**原"守护进程代理"模型——域名清单/代发/记账整体作废,netd/独立代理
  进程死胎,ObProxyRequest 命令删除。**实施机制唯一 = netns,无备选路径,owner
  裁决;同日修订:setns 运行时搬运被否——socket 绑定创建时所在 netns,搬运不
  迁移存量 socket(囤货漏网),故实施形态定为出生制+重启切换**):
  **默认开**:联网是模块原生能力——nobody 直连,不经任何中间人,零损耗零组件。
  **关 = 出生制**:模块进程由 daemon clone(root 在手;旗标按开关组装,
  net=off ⇒ `CLONE_NEWNET`——2026-11-09 与 RL-07b 统一为同一出生动作,取代
  独立 `unshare` 调用)——子进程**出生在空网络命名空间**(无网卡、无路由、
  无 DNS):socket 随便开、connect 语义正常,但每个字节都出不去(ENETUNREACH =
  "这台机器没网"的正常错误,无"被拦"指纹);它一生拥有的每个 socket 都生在
  空 ns 里,**囤货 socket 从根上不存在**(没有"先有网再断网"的窗口);
  无 syscall 拦截清单 = 无绕过面;按进程粒度(非按 uid,不误伤他者)。
  lo 姿态(P8,2026-11-09):**UP**——daemon 在 drop uid 前拉起(root 在手,
  一次 SIOCSIFFLAGS);loopback 永不出 ns,零出网代价;"lo up + 无其他接口"
  = 容器世界标准像,绑 127.0.0.1 的库不再 EADDRNOTAVAIL。
  **切换 = 重启模块**(owner 裁决,运行时拨开关的落位方式):收工通知(RL-21
  已有机制)→ 模块退出(句柄随进程关闭自动失效,登记干净撤销)→ daemon 按新
  开关状态重新拉起(开 = 正常 clone;关 = clone 加 CLONE_NEWNET)。**setns 搬运运行中
  进程的场景被重启制整体删除**——不存在"搬家"动作,无中间态;内核监听规则
  是内核态登记,重启不丢(§6.6 红利);模块内存状态丢失 = 生命周期边界语义,
  文档纪律:联网开关切换视为模块生命周期事件(模块本就须正确处理被拉起/收工)。
  **按需建毁**(孤儿 netns 议题裁决):空 netns 仅在拉起"关网模块"时创建,
  进程退出即销毁——**无模块被断网时,系统里不存在任何框架 netns 对象**,
  零孤儿指纹。开关状态记 daemon 注册表,开机重放(决定下次拉起时的 clone 形态)。
  **对抗面分析(2026-11-09 商讨定案)**:
  ① netns ID 内核随机分配,格式与系统原生 ns 一致——检测器无"合法名单"可闭集
    比对(Android 上独立 netns 的进程本就常见:VPN 守护、隔离组件);出生制
    下进程"从来如此",连"曾被搬家"的痕迹都不存在,与常态进程完全同像;
  ② app 造不出 nobody 进程:setuid(9999) 需 CAP_SETUID,内核拒绝——"同 uid
    侦察邻居"路线在入口即死;
  ③ 即使假设同 uid 存在:SELinux 域不随 uid 走,untrusted_app 域对我们的
    /proc 条目策略层拒绝;**模块域继承 daemon(root 侧),精确行为
    (type_transition 有无)为首批真机验证项**;
  ④ Android app 本就无法 ps/遍历其他进程(SELinux /proc 限制)——模块进程
    对 app **根本不存在**;
  → 残余面 = 仅 root 取证者(可读 ns 归属、停机取证)——root 理论上不可防御
  (owner 定论,2026-11-09),与硬件级自省同级,§9"明确不管";且仅"正被断网"
  的模块暴露,默认开的模块与众生同 ns。
  借道(binder/文件旁路外传)为数据级残余,防线 = 作用域授权,诚实标注。
  **实时化路径评估(2026-11-09 定案:不采用,出生制即终局,勿复活)**:
  ① cgroup-bpf egress/connect 钩子——逐包封、进程存活、存量 socket 同杀,但
  connect 拒绝 = EACCES"被策略拦"指纹(丢"无被拦指纹"立论);daemon 死 = link
  释放 = 静默复网(fail-open,须 bpffs pin 钉死);依赖 CONFIG_CGROUP_BPF 及与
  netd 程序的共存面。② 私有 netns + veth 管道——拔 veth 击毙存量连接、保离线
  指纹,但 veth/NAT 及其清理路径 = 本框架第一批需自写清理的持久对象,崩溃窗口
  留孤儿。出生制与 Android 权限开关语义同构(空闲即触、在跑 ≤ 宽限期;无常驻
  模型让空闲成为常态),已足。
  **模块知情权(2026-11-09 裁决)**:模块**应当**能知道自身联网状态与拉起/收工
  原因——对模块隐瞒不是防御目标(模块是受管控方,知与不知不改变其能力;接口
  清单自探本来就能区分,API 只是把必然发生的事标准化)。**具体提供方式在实现期
  确定,本档不预设任何方案。**
  `[联网管控整个属于控制面:daemon 用 root 原生能力做管理的事,数据面/内核 Gateway 不参与;彻底性来自"物理无路"而非"规则拦截"——有 fd 也上不了网;全部机器(收工通知/宽限强杀/重拉)皆是 RL-20/21 已有部件,零新增]`

- **RL-07b** 同 uid 模块隔离 = ns 出生制(2026-11-09 裁决;背景:owner 定调
  "V1 即终局"+"模块同 uid 必须隔离",原 §3/§9"per-module uid 留给下一版"表述
  作废):**uid 不动(nobody 9999 共享,"与众生同像"判决不变),隔离靠命名空间
  缺席**——spawn 时 clone(CLONE_NEWPID 与 CLONE_NEWNS)(net=off 追加 CLONE_NEWNET,
  与 RL-07a 同一出生动作):
  **① pidns 关进程互访门**:一切"按 pid 指名"的攻击面——ptrace / process_vm_readv/
  writev / pidfd_getfd / kcmp / perf_event_open / kill / /proc/<pid>/fd magic link
  (偷句柄、借 socket、注入执行流"借 B 的能力位+作用域")——内核一律在**调用者的
  pidns 内**解析 pid,兄弟模块在彼此宇宙里**没有 pid** → 构造性不可达(ENOENT/
  ESRCH),**不是被拦截,是对面无人**。与 netns"囤货 socket 从根不存在"同构:
  物理无路,非规则拦截。模块即自身 pidns 的 init(getpid()==1——模块可见、
  外界不可见,无对抗意义);RL-21 先礼后兵不受影响(daemon 居 init_pid_ns,
  祖先 ns 可指名后代)。
  **② mountns 轻监狱关文件互访门**:唯一共享可写面 = 模块树——出生时(先递归转
  私有传播 MS_PRIVATE|MS_REC,防子 ns 挂载事件传播回宿主)tmpfs 影子化 + 仅回绑
  自身目录(回绑真实目录,写入落真实存储);重挂 /proc 只见自身 ns。系统其余
  部分保持只读可见(模块使用系统组件的自由不受限——轻监狱,非全监狱:pivot_root
  全监狱不采用,砍模块使用系统组件的自由,与"本来能做的都能做"相悖)。
  **③ 配套纪律**:Gateway 解析目标 pid 一律在 init_pid_ns(KPM 自选解析域);pid
  对模块是**不透明数**("正门是唯一路"的推论——模块没有任何直接触碰进程的合法
  用途);今后新增任何共享可写路径必须过隔离审计;spawn 流程加
  prctl(PR_SET_NO_NEW_PRIVS)(封 exec 提权路径,2026-11-09 随本条定案)。
  **被否/被取代方案(防复活记录)**:per-module uid(维持 nobody 判决:自定义 uid
  自挂牌、多用户 uid 算术要自发明);seccomp 否决表为主防线(被 ns 出生制取代,
  留作纵深选项,不排期);改 yama/ptrace_scope(设备全局变更,客人不是主人);
  KPM 强制 dumpable(内核开始监管模块 = 新机制,违背纯执行器,且有 exec 竞态窗)。
  **残余(任何隔离机制的门外)**:合谋(SCM_RIGHTS 互传/自愿共享,两厢情愿不归
  隔离管,防线 = 作用域授权);RL-07a 对抗面分析①-④逐字不动(nobody 不变,
  app 侧视角不变)。
  **首批真机核实**:宿主内核对 clone(NEWPID/NEWNS)与 mountns 重挂/回绑的放行;
  SELinux 模块域(继承 daemon 侧)对 mount/clone 旗标的策略(与 RL-07a ③ 同一
  验证族扩展);magic link 对 anon_inode 句柄可达性(应在 pidns 外已不可达)。
  `[uid 栅栏要推翻 nobody 判决;seccomp 规则表逐 syscall 封 = "物理无路"退化回"规则拦截"。ns 出生制与 netns 断网是同一个物理动作服务两件事——一次 clone 全套定形]`

- **RL-08** 句柄制鉴权(2026-11-08 句柄定稿改写):通信走标准内核文件接口
  (read/write/ioctl on 框架句柄),**鉴权在 fd 层一次完成**——内核句柄表就是
  凭证本身(文件描述符不可跨进程猜取/伪造,fd 表项带属主)。命令分发时三层
  不可重排:**查句柄**(fd → 模块登记项,内核一次表查询)→ **能力位**(该句柄
  烙印的 allowed_ops 含此命令族?)→ **目标作用域**(RL-04a:目标包名在该句柄
  作用域清单内?)。越权返回 `-EACCES`;`-EPERM` 保留给框架级拒绝。
  模块卸载/强杀/进程崩溃 → 句柄 close 回调**自动**撤销全部登记(无需显式
  撤销代码);重启后守护进程重放注册,内核铸造新句柄。
  `[句柄即凭证取代 128 位 token:不可猜(非数值密码,是内核记账)、不可偷(仅持有进程可用)、死亡即失效(close 回调免费)。曾经 token 体系的全部难题(常数时间比较/递送通道/复用防护)被 fd 语义整体消解]`

- **RL-09**(句柄制下大幅简化)内核登记表是运行时状态,重启即清;守护进程磁盘
  注册表存**非密**信息(模块 id/能力位/作用域包名清单),开机重放、内核重新铸造
  句柄。句柄数字本身毫无价值,无需保密——泄了也只在持有进程内有效。
  `[持久化属于 daemon;内核态零持久化 = kstorage 不用]`

### D. 契约纪律(ABI 是唯一接口)

- **RL-10** **不做 SDK。** 模块侧唯一契约是 UAPI 头文件 + `docs/native-api.md`。
  不提供客户端库、不提供 wrapper、不发布示例以外的"官方运行时"。
  `[SDK = 链接关系 = 许可证传染争议 + 版本耦合;syscall ABI 是 arm's-length 边界,Linux 世界 30 年验证过的模式。模块闭源合法性依赖此边界]`

- **RL-11** 命令码**永不重编号**。分配区间:`0x1000+` Ke、`0x2000+` Mm、`0x3000+` Ps、
  `0x4000+` Zw、`0x5000+` Ob、`0x6000+` Ldr、`0x7000+`(待命名方法级 hook 族,预留,§5)。
  废弃的码保留取值并返回 `-EOPNOTSUPP`;新增只追加。
  任何 struct 布局变更必须升 `KEPOSED_PROTO_VERSION`(gateway 对不匹配返回 `-EPROTO`)。
  `[无 SDK 保护的生态里,ABI 破坏 = 所有第三方模块同时死亡;协议文档与 UAPI 头文件必须同 commit 变更]`

- **RL-12** 所有 UAPI 结构体:定宽类型(`u32/u64`)、显式 `__attribute__((packed))`(布局敏感处)、
  预留字段、统一以 `u16 proto_ver; u16 cmd;` 开头。错误码是 Linux errno,
  `docs/native-api.md` 的错误表是规范。
  `[跨编译器/跨语言(模块可能是 Rust/C/Go)的结构体布局必须显式钉死]`

### E. 生态隔离纪律(防污染是双向的)

- **RL-13** 框架模块的清单文件**必须**叫 `manifest.toml`,**绝不**叫 `module.prop`;
  模块目录**必须**在 `/data/adb/modules/keposed/modules/` 之下。
  `[叫 module.prop = KSU/LSPosed manager 把我们的模块误认成自己的模块 = 双向污染;嵌套目录对 KSU 顶层扫描不可见,卸载框架 = 连带清空]`

- **RL-14** 框架**绝不**依赖任何宿主私有接口:SukiSU 的 extension ioctl、APatch 的管理器
  app、任何 `me.bmax.*`/`me.weishu.*` 的包名约定。加载是唯一与宿主的接触点。
  `[依赖宿主私有接口 = 框架被绑死在单一管理器上,与"加载器无关"的定位矛盾]`

### F. 许可证纪律

- **RL-15** 内核与 daemon 源文件 SPDX 为 `GPL-3.0`;`uapi/` 头文件为
  `GPL-3.0 OR Apache-2.0` 双许可;协议文档同样双许可。KernelPatch 上游是
  `GPL-2.0-or-later`(已核实其源码 SPDX),GPL-3.0 调用其导出符号兼容。

  `[双许可 UAPI 是闭源模块合法性的支点;单方面收紧/放宽都是生态事故]`

### G. 定位与观测纪律(2026-11-08 技术定稿追加)

- **RL-16** 符号解析纪律:全部符号在 `KPM_INIT` 一次性预解析进函数指针表;热路径
  (hook 回调/命令分发)**零解析**。每个原语声明符号依赖,解析失败自动级联降级为
  `-EOPNOTSUPP`(用户在 WebUI 看到"此内核缺少 X,Y 能力不可用",不是神秘 panic)。
  版本矩阵(PTE walk 族)只允许存在于 `mm/` 模块内。resolver 一律
  `kallsyms_lookup_name_by_suffix`(CFI/LTO 克隆),优先函数符号、避免数据符号。
  `[热路径解析 = 每次调用付查找成本 + 失败面进入 syscall 路径;分散的版本 if/else = 每个内核一个分支炸弹]`

- **RL-17** 观测纯度(RL-01 的强化升级):**对目标的任何原语操作不得改变目标可观测的
  状态**。具体:Mm 读取/搜索族默认 present-only 逐页谓词(内核页表 walk,只读)——
  present 才读,不 present 跳过,**绝不替目标分配页**(内存蜜罐防御:app 可用
  mincore 轮询自己未触碰页的驻留位);zram 换出页同样跳过(不触发解压回填)。
  触碰冷页必须走显式 `MM_READ_FAULTIN` 变体,痕迹决策留给模块作者。
  `[读取留痕 = "不可检测"从构造保证退化为实现质量;蜜罐页被缺页分配 = 向目标宣告"有东西在读我"]`

- **RL-18** ART/宿主结构偏移**永不进内核**:内核只提供通用机制(Ldr 模块/符号解析、
  Ke 链式指针读取、Mm 批量读);版本知识(锚点策略 + 每跳偏移)住在用户态
  locator profile(JSON,按 Android 版本分发)。新 Android = 更新 profile 数据,
  内核零重编。
  `[偏移进内核 = 每年重编 KPM + 内核承载最易碎的知识;profile 是数据,数据可以热更]`

- **RL-19** Zw 塑形注册**必须** `hook_syscalln_override`,绝不用 `hook_syscalln`
  (后者被 KP 的 su_syscall_gate 过滤——塑形目标是普通 app,普通注册的回调
  **静默永不触发**,见 §6.1);且回调**首行**必须 uid 快速失败(单次 cmp)。
  `[用错 API 不报错、不崩溃,只是安静地什么都不发生——最危险的失败模式]`

### H. 生命周期与门禁纪律(2026-11-08 追加)

- **RL-20** 无常驻模型:模块**不常驻**——平时不存在(零进程零内存),目标进程
  诞生事件(内核在 execve 最早瞬间发现)→ 守护进程拉起关心它的模块(事件写进标准输入)→ 模块一次生命周期内干活、登记监听规则 → exit 退出。进程退出
  = 模块本轮结束,无崩溃恢复复杂度(下次事件再拉起)。守护进程对同模块做简单
  节流:在跑不重复拉,事件排队。**"干完"的精确定义(2026-11-09 澄清)= 收工
  (RL-21:作用域内目标全死/收工通知)**,不是"登记完毕"——一切登记(盯防/
  钉死/塑形/hook)都是**模块的活**:驱动只是执行的手,模块在场 = 登记的执行
  前提;模块进程死亡 → 登记全部自动撤销(RL-08,一字不改)。"无常驻"指
  **平时不占进程**(零进程零内存),不是"登记完就走"。
  `[常驻模块 = 常驻内存/常驻进程表条目/崩溃恢复复杂度三宗罪;值班期间的持续动作由驱动承担执行(盯防轮询/影子页切换),不需要模块自己写循环——但模块进程必须在岗承载意志]`

- **RL-21** 先礼后兵(目标退出联动,2026-11-08 裁决):目标进程退出 → 内核通知
  守护进程 → **逐个告知**:作用域内每个目标死亡都通知模块("某某退出了",模块
  自行撤监听、调整策略)→ 作用域内目标**全部**死亡 → 发"收工"通知(礼)→
  宽限期(用户可调,默认 3 秒)→ 仍未退出 → 强杀(兵)。目标进程注销时其关联
  监听规则自动清理。
  `[生命周期强制对齐:目标生模块起、目标死模块收、赖着不走替你走;逐个告知让多目标模块能精细收尾,全死强杀才不冤]`

- **RL-22** 句柄制定稿(2026-11-08 二次裁决,**取代**原 syscall+暗号通道设计;
  token/常数时间比较/透传失败响应等前设计全部作废):通道 = 开机一次 syscall
  握手(带魔法数,root 发起)→ 内核分发框架句柄(anon fd)→ 之后所有通信走
  标准文件接口。模块句柄经 SCM_RIGHTS 递进子进程。**syscall 入口只在开机
  用一次**:选号从"终生冻结的重大决定"降级为"挑个不撞车的"(启动探测照旧,
  应答异常 = 拒绝启动,宁死不撞车)。app 探测该号(若它真去调):极低频流量 +
  透传真 handler = 与原厂一致。环境先例:KSU 2025-11 起即此模式(reboot 握手 →
  anon_inode:[ksu_driver] fd → 全 ioctl);binder/ashmem 等系统组件同构——
  nobody 进程持一个匿名 fd 毫无异常。
  `[句柄制的本质:把"验证身份"从每次调用一次,折叠成 fd 表一次;凭证难题被内核文件语义整体吸收。验证性风险(诚实):严格 SELinux 策略下 nobody 对 fd 的 ioctl 是否放行——首批真机必须验证项]`

### I. 方法级 hook 纪律(2026-11-08 深夜定稿追加)

- **RL-23** 方法级 hook 的唯一合法形态 = §6.8 终局方案(影子页双视图 + 读透明 +
  **整模块映像跳板**),**v1 一次性实现**(不分期,owner 裁决:体验/稳定/安全 >

  ③窗口期对目标进程的扰动只有微秒级时序(异常陷入),无任何持久痕迹;
  ④回调规矩 = **三条**(2026-11-09 第二轮重构改写;原"纯计算/不摸目标内存"
  契约作废——与 P2 直接互斥,且整模块映像下回调可正常使用自身全局量):
  (a) 不以目标身份发系统调用——以目标身份 mmap/brk = RL-02 痕迹、污染目标

  (b) 不触碰目标线程的 TLS(thread-local storage);
  (c) 跑在目标线程自己的栈上(同 LSPosed;深递归自责)。

  owner 裁决:故意延时合法,非恶意——"如果是故意的,就不是我们的问题";

  `[四象限设计空间已闭合(内核数据/内核代码/模块代码目标跑/模块代码自家跑,§6.8),不存在第五种 fundamentally 不同的方法——勿再重新开放;更好方案将来只替换跳板策略]`

## 3. 反直觉设计决策("看起来错"但正确的裁决)

当你产生"这段该重构/修复/补充"的冲动时,先查此表:

| 直觉冲动 | 为什么是错的 | 正确认知 |
|---|---|---|
| "内核侧加个小型脚本引擎/规则解释器,模块就简单了" | 内核=执行器是安全模型本体,不是实现偏好 | 决策逻辑住用户态模块;内核只认命令码(RL 见 §2.A/§1) |
| "给模块 SDK 会更友好" | SDK 制造链接关系 = 许可证传染 + 版本耦合 | ABI + 头文件是唯一契约(RL-10) |
| "token 存 kstorage 持久化更省事" | kstorage 重启即失 + token 落盘=可窃取 | daemon 侧重放注册信息,内核重新铸造句柄(RL-09;token 已被句柄制取代) |
| "模块要隔离就该每模块一个独立 uid" | uid 栅栏要推翻 nobody 判决(自定义 uid 自挂牌),多用户 uid 算术要自己发明 | 隔离的正确形态 = ns 出生制(RL-07b):uid 不动,兄弟模块在彼此 pid 宇宙里**不存在**——构造性隔离,非规则拦截 |
| "hook 每个目标 syscall 一次,粒度细控制准" | per-syscall hook 产生 per-syscall trampoline 时序指纹 | 用 `hook_syscalln` 自动策略:优先全局挂 `invoke_syscall` 单点分发(§6) |
| "detected 进程自哈希数据段 = 框架失败" | 数据修改后自校验确实可发现 | 这是文档化的残余对抗面;校验输入可在 syscall 层反向塑形,纵深在内核侧。诚实标注,不假装零痕 |
| "方法级 hook 也顺便支持一下,扩大生态" | ~~与 RL-01 直接冲突~~ **2026-11-08 深夜推翻:非 LSPosed 式实现(影子页双视图)不违反零注入** | 方法级 hook 进 v1 终局形态(§6.8/RL-23);与 LSPosed 是**互补不是竞争**(口径修正,owner 裁决):同一目标的不同方法——他们进程内生态兼容,我们进程外无痕;native 域在他们设计域外、在我们域内,属互补生态位的差异化能力 |
| "gateway 用 binder/socket 更标准" | binder 在 KPM 里不可用;自建专用 socket = 环境可检测痕迹 | 句柄制(开机一次握手 → anon fd,RL-22/§6.7;先例 KSU 2025-11)——fd 是内核记账的凭证,非自建 socket |
| "加载失败自动降级成 .ko 试试" | 框架不碰加载(RL-14) | 加载失败 = 如实报错给用户,让宿主解决 |
| "给 WebUI 加远程访问方便调试" | 攻击面 | WebUI 仅 localhost(KSU WebUI 惯例) |
| "hook_syscalln 是标准 API,注册就用它" | KP 全局分发器的 su gate 只放行 root/su-allow/manager uid;塑形目标是普通 app——普通注册的回调**静默永不触发** | 必须 `hook_syscalln_override`(RL-19,§6.1);回调首行 uid 快速失败 |
| "skip_origin 伪造返回最简单" | 比真调用**更快**也是时序指纹(真 statx 冷路径 μs 级,伪造 100ns 返回 = 分布异常) | 策略优先级:重定向 > after 改写 > skip+延迟垫底(§6.3 R4) |
| "规则按 syscall 号建模,一个一个来" | openat 塑形而 newfstatat 不塑形 = open 成功 stat ENOENT 的逻辑矛盾,比时序泄漏更糟 | 路径规则落到整个 stat/open/access 族 + compat 孪生(§6.3 R5) |
| "进程事件要 hook wake_up_new_task 或 netlink" | 新 hook = 新符号 = 新时序面 | Ps spawn/exit 寄生在 Zw 层 execve 回调,零新增(§6.2) |
| "ART 偏移矩阵编进内核更高效" | ART 每年一版;偏移进内核 = 每年重编 KPM + 内核承载最易碎知识 | 机制进内核(Ldr/Ke 走链),知识进用户态 profile(RL-18,§6.5) |
| "跨进程读直接 access_process_vm 整段读最简单" | 读冷页触发缺页分配 = 内存蜜罐可检测(app 用 mincore 轮询驻留位) | present-only 逐页谓词构造性排除(CE "Active memory only" 教训,RL-17,§6.4) |
| "KPM 用 C++/Rust 更现代" | KP 工具链纯 C;freestanding 无 libstdc++;Rust 需 no_std 重实现整套 KPM ABI = 纯负担 | KPM=C;现代性由 daemon(Rust)承担(§4 语言矩阵) |
| "daemon 用 Go/Kotlin 也行" | Go:二进制体积 + raw syscall 边角失控;Kotlin:root 守护进程拖 ART 运行时,启动/被杀重启全是麻烦 | Rust(ksud 先例 + bindgen 消费 uapi 单一事实源) |
| "模块给 shell/自定义 uid,再配点权限" | shell 权限过高(adb 组旁门);自定义 uid 可被 app 经用户管理服务枚举 = 自挂牌 | nobody(9999);联网管控 = 布尔开关 + netns(RL-07/07a) |
| "模块要常驻才能持续监控" | 轮询循环不需要活着的进程——盯防轮询/影子页切换由驱动执行;但规则是模块的意志,模块进程值班至收工 | 无常驻 = 平时不占进程;值班期间模块在岗承载意志,不用自己写循环(RL-20 澄清) |
| "每次调用都要带 128 位暗号验身份" | 每次验证 = 每次付比对成本 + 一整套凭证管理难题(防猜/防偷/递送/复用) | 句柄制:开机一次握手,fd 即凭证——验证折叠进内核 fd 表,凭证难题被文件语义整体吸收(RL-08/22;先例 KSU 2025-11) |
| "网络代理给模块直接发权限更简单" | ~~守护进程代理~~ **2026-11-09 废除代理模型(owner 裁决):联网是模块原生能力,默认开**;管控 = 布尔开关 + netns 物理断网(有 fd 也上不了网,无指纹) | 域名清单/代发/记账全部删除;netd 死胎;ObProxyRequest 命令删除(RL-07a) |
| "方法级 hook 分期做:v1 数据钉死,v2 影子页" | 分期 = 中间形态被推翻重做;地基(异常入口/页表手术/ART 定位)是共用一次性工程 | v1 一次性实现终局形态(§6.8);体验/稳定/安全 > 开发成本是项目级原则 |
| "跨进程调用模块函数要挂起目标线程等模块算完" | 两次进程切换 50-200μs + 挂起/死锁/超时语义裂缝(upcall 已二次否决:2026-11-09 复活评估,owner"我需要支持热方法") | 整模块映像:窗口期目标线程直接执行模块映像,2-5μs 无挂起(§6.8) |
| "改方法页字节写跳转就行" | 代码区自哈希校验一个字节都不能动 | 影子页双视图:读/校验恒见原样,只有"执行取指"瞬间走影子(§6.8 读透明) |
| "hook 回调只能写零依赖裸函数(单页搬运的必然)" | 搬一页只带 .text,全局量/GOT/TLS 全不在场——开发体验死亡,owner 三条件(不注入/高热/开发体验友好)全崩 | 整模块映像:映像 = 模块自己的内存,代码+全局数据完整着装,回调里随便用(§6.8 第二轮重构) |
| "模块登记完就该退出,规则让内核替它跑" | 规则是模块的意志;模块不在场 = 意志不在场 = 规则没有主人。内核替死去的模块继续做主 = 往内核塞决策 | 模块在场 = 一切登记的执行前提;驱动只是执行的手;进程死 = 登记全灭(RL-08/RL-20 澄清,2026-11-09) |
| "模块在窗口里赖着/故意延时需要超时强拆" | 故意延时合法(owner:非恶意);强拆反而引入"原方法双跑"等新问题 | 窗口时长不设限;可见性靠验收线构造保证(映像永不可见),与窗口长短无关(2026-11-09) |

关键数据流(一屏版):

```

  能力表初始化) → KSU service.sh 拉起 keposedd
  → keposedd 一次性 syscall 握手(带魔法数,root) → 内核分发框架句柄(anon fd)
  → 从磁盘注册表重放模块注册(内核为每模块铸新句柄,烙印能力位+作用域)
  ——注意:此时不 spawn 任何模块(无常驻,RL-20)

模块生命周期(无常驻模型,RL-20/21):
  目标进程诞生(execve 最早瞬间,内核 Ps 寄生回调) → 唯一通知守护进程(点对点)
  → 守护进程查作用域登记表(谁关心这个包名) → 拉起对应模块
    (clone 出生制:pidns/mountns 隔离 + netns 按开关 → nobody → exec,RL-07/07b;模块句柄经 SCM_RIGHTS 递进子进程;事件写标准输入)
  → 模块干活:对句柄 read/write/ioctl(读写内存/搜索/登记监听规则 MmWatch;
    联网 = 原生能力直连 RL-07a,开关默认开)→ 收工 exit 退出(本轮结束;
    干完 = 收工 RL-21;句柄随进程关闭自动失效)
  运行中:值变化 → 监工自动执行(改写等——执行是驱动的手,意志是值班中模块的,2026-11-09 口径)
  某目标死 → 逐个通知模块(撤监听/调整) → 作用域内目标全死 → "收工"通知
  → 宽限(用户可调,默认 3s)→ 未退 → 强杀;目标注销自动清理其监听规则

模块调用(句柄制): 模块对句柄 ioctl/read/write,帧{proto_ver, cmd, args}
  → 内核三层检查(RL-08): 查句柄(fd→登记项)→ 能力位 → 目标作用域(RL-04a)
  → 全过 → 分发到 ke/mm/ps/zw/ob 例程;不过 → -EACCES
  → 例程经 access_process_vm / hook_syscalln 作用于目标进程

syscall 塑形: 目标进程调 openat/read/... → KP invoke_syscall 全局分发
  → KePosed Zw 层 before/after 回调(受 RL-03 约束)→ 结果塑形 → 返回目标

ART 定位(原语组合示例,§6.5): Ps spawn 事件 → ART 就绪锚点探测
  → LdrGetModuleHandle(pid,"libart.so") → LdrGetProcedureAddress(锚点符号)
  → KeFollowPointerChain(profile 偏移,双走比对) → MmCopyVirtualMemory 批量读出原 dex

卸载: 用户在宿主管理器卸载 KSU 模块 → daemon 停止(按 RL-21 流程收尾在跑模块)
  → 句柄全数 close(登记自动撤销) → KPM_EXIT 对称卸载全部 hook(RL-06)
```

## 6. 内核侧实现约束与技术定稿(已对上游源码核实)

内核代码运行在 KernelPatch(当前 0.13.9)运行时内。§6.1 是**已核实**的上游事实
(来源:KernelPatch 仓库 `doc/en/*.md` 与源码),新 Agent 不需要重新考古;
§6.2-§6.5 是 2026-11-08 六轮技术定稿的结论固化——**它们是裁决,不是草案**。

### 6.1 KP 运行时事实

- **生命周期宏**:`KPM_NAME("keposed")`(全内核唯一,控制/卸载的标识符)、
  `KPM_VERSION/LICENSE/AUTHOR/DESCRIPTION`、`KPM_INIT(fn)`、`KPM_CTL0(fn)`(用户态
  控制消息)、`KPM_EXIT(fn)`。init 返回非 0 = 加载失败。
- **syscall hook**:用 `hook_syscalln(nr, narg, before, after, udata)`——自动策略,
  优先在 `invoke_syscall`(所有 syscall 的公共必经点)挂**单个**全局 hook,syscall 表
  零修改、无 per-syscall 时序指纹;`invoke_syscall` 不可用时回退 `el0_svc_common`,
  再回退 per-syscall 的 `fp_hook_syscalln` / `inline_hook_syscalln`。
- **⚠️ _override 陷阱(Zw 层生死级事实,RL-19 的来源)**:全局分发器启用时,
  `hook_syscalln` 注册的回调会先过 KP 的 `su_syscall_gate`(只放行
  uid==0 / su-allow / trusted-manager,见 sucompat.c)——**Zw 塑形的靶子是普通
  app(非 su uid),普通注册的回调不会触发,而且是静默不触发**。必须用
  `hook_syscalln_override`(注册带 `bypass_gate=1` + `allow_skip=1`,KP 的
  magic supercall 用的就是这个口子)。推论:bypass 注册的回调对该 nr 的**所有进程**
  都会进入——回调第一行必须 uid 快速失败(单次 cmp;该常数对所有调用者一致,
  跨进程对比不可见)。初始化时用 `syscall_hook_global_enabled()` 探测模式。
  另:`skip_origin` 仅在 handler 粒度(invoke_syscall)被尊重,吞 syscall 时必须
  同时设 `args->ret`(分发器会把它写进 regs->regs[0])。
- **参数访问**:一律 `syscall_argn(args, n)` / `set_syscall_argn(args, n, val)`,
  绝不裸读 `args->argN`——带 syscall wrapper 的内核首个参数是 `pt_regs *`。
- **用户态访问**:hook 回调内用 `compat_copy_to_user` / `compat_strncpy_from_user`
  (`kputils.h`),不是裸 copy_to_user。
- **inline hook**:`hook_wrap(func, argno, before, after, udata)` 链式(每函数上限 16
  项,插入序,无优先级);同一回调指针重复注册返回 `HOOK_DUPLICATED`。
  卸载用 `hook_unwrap(func, before, after)` 传原指针。
- **进程定位与 kfunc 库存**:`find_get_task_by_vpid(pid)` / `get_task_mm(task)`——KP 在
  `kernel/linux/include/linux/sched/` 提供了 kfunc 封装头,**优先用这些头**。
  KP 启动时自解析的 kfunc 远不止这两个(ksyms/misc.c,已核实):完整 cred 族
  (`prepare_kernel_cred`/`commit_creds`/`override_creds`/`revert_creds`)、
  pid/task 族(`find_task_by_vpid`/`pid_task`/`get_pid_task`)、mm 族
  (`mm_access`/`get_task_exe_file`)、usercopy 助手(`memdup_user`/`strndup_user`)、
  `_raw_spin_lock` 族、`stop_machine`——写代码前先查库存,已有的直接调。
  **`access_process_vm` 零覆盖**——Tier 2 自行解析(见 §6.2)。
- **CFI/LTO 克隆**:resolver 一律 `kallsyms_lookup_name_by_suffix(name)`,绝不用裸
  `kallsyms_lookup_name`——Clang CFI 内核里函数有 `.cfi_jt` 跳板,LTO 生成
  `name.llvm.<hash>` 克隆,裸精确名会 miss。inline hook 目标尤其要验证 hook 到的
  是函数体还是跳板(语义不同)。
- **kallsyms 根信任**:上游 5.7+ 不再导出 `kallsyms_lookup_name`;KP 的运行时查找
  是自建的——kptools 在**安装时**离线解析 boot.img 把地址烘焙进 kpimg(predata)。
  因此 Tier 2 对 KPM 是可靠地基。已知坑:`CONFIG_KALLSYMS_ALL=n` 的内核 kallsyms
  缺数据符号——**resolver 优先函数符号,避免依赖数据符号**。
- **运行时版本常量**:`kver`(内核版本码)、`kpver`(KP 版本码)可直接引用。
- **热路径纪律**:syscall hook 的 before/after 是热路径——RL-03/RL-04 的来源。

已知边界(上游文档明示):hook 框架 ARM64-only;fp 链上限 32 项;
`HOOK_CHAIN_FULL`(16 项满)是真实错误码,KePosed 自身的 Zw 塑形层要做配额管理,
不能把 KP 的链配额吃光。

### 6.2 符号定位金字塔(原语 ↔ 定位链对照)

核心原则:**把最多的能力压在最稳的层**。塔顶零成本永固,塔底版本敏感。

| 层 | 手段 | 可靠性 | 承载 |
|---|---|---|---|
| Tier 0 | syscall 号(arm64 冻结 ABI) | 永固,零成本 | Gateway 通道、Zw 塑形、Ps 事件(寄生 execve 回调) |
| Tier 1 | KP kfunc(启动期已解析) | 免费 | 进程定位、cred 操作、usercopy、mm_access |
| Tier 2 | `kallsyms_lookup_name_by_suffix` | 高(安装时烘焙) | `access_process_vm` 等自解析函数 |
| Tier 3 | 枚举+结构锚定(`kallsyms_on_each_symbol` / init_task→init_mm / BTF) | 版本敏感 | 兜住被内联/改名符号;BTF 给类型不给地址 |
| Tier 4 | PTE walk 族(pud/pmd/pte_offset_map/TLB flush) | **唯一硬骨头** | RO 页写入;签名 5.10→6.6 间漂移(pte_offset_map 5.13 改 API) |

- **Ps spawn/exit 事件零成本实现**:不 hook `wake_up_new_task`、不用 netlink——
  **寄生在 Zw 层 execve 回调**(app 冷启动必经,目标 uid 命中即入事件队列),模块经
  Ps 族命令消费。零新增 hook、零新增符号、零新增时序面。
- **RO 页写入**(V1 即终局,2026-11-09 收编进 v1;原"v1.5 分期"措辞废除):
  RW 页写入是主场景(游戏数值都在 RW 数据段),`access_process_vm` 内部走 GUP
  已覆盖大部分;目标页只读时手工 walk(Tier 4 PTE 矩阵,RL-05 唯一实现)随 v1
  一并交付——版本矩阵集中在 mm/ 模块(RL-16),不以"下一版"延后。
- **明确拒绝**:内存特征码扫描(版本脆弱)、硬编码机型偏移(每机型爆炸)。

### 6.3 Zw 层时序防御模型(R1-R6)

app 的测量手段只有 vDSO `clock_gettime` 夹逼:同进程跨 syscall 对比、同 syscall
跨时间对比(冷启动存基线)、10⁶ 采样统计分辨(安静系统 ~10ns,真机噪声
~100ns-1μs)。防御目标:**被塑形 syscall 的延迟分布与自然分布不可区分**。

成本分层(①②③对所有进程/所有 syscall 恒定——任何差分对比不可见;对抗面只在 ④⑤):

```
① transit + KP 全局分发器     —— 全部进程 · 全部 syscall · 恒定
② su gate 评估 + 槽位扫描      —— 同上(≤64 槽)
③ 回调入口 + uid 快速失败     —— 被 hook nr 的全部调用者 · 同一常数(跨进程对称)
④ 规则匹配(usercopy+hash)    —— 仅目标进程 · 仅该 nr · ~100-300ns
⑤ 塑形工作                    —— 仅命中调用 ← 真正的对抗面
⑥ 真 syscall 执行             —— μs 级自然方差(dcache/inode/调度抖动)· 天然掩体
设计目标:③④⑤ 的增量沉入 ⑥ 的自然方差
```

- **R1 快速失败顺序**:uid cmp → nr 位图 → 规则匹配(非目标进程第 1 步出去)。
- **R2 匹配成本封顶**:路径规则安装时预计算 hash 前缀;热路径一次有界 usercopy
  (≤256B)+ 比较。路径类 syscall 自然方差 μs 级——增量深埋噪声。**这是选
  openat/statx 族作主塑形面的物理理由**。
- **R3 紧方差警戒**:getpid 类延迟分布极窄(几十 ns 方差),统计可分辨——不碰,
  或带 latency_floor 垫底(有界自旋,原子上下文安全)。
- **R4 伪造不是免费的**:skip_origin 让调用**变快**——比真快也是指纹(真 statx
  冷路径 μs,伪造 100ns 返回 = 分布异常)。策略优先级:**重定向 > after 改写 >
  skip+垫底**。重定向(改路径参数让真 syscall 跑真文件)延迟完全自然——KP
  sucompat 正是此法(改 filename 指针指向合法路径)。
- **R5 路径建模而非 syscall 建模**:一条路径规则落到整个 stat/open/access 族
  (openat/newfstatat/faccessat/statx)+ compat 孪生(32 位探测路径)——
  open 成功而 stat ENOENT 的逻辑矛盾比时序泄漏严重得多。
- **R6 gateway 自身反探测**:非握手调用(对握手号)**原样透传真 handler**(不碰参数、
  不返回错误)——syscall 扫描器逐号探测看到的是真行为。绝不 -ENOSYS 短路。

残余(记录不处理,2026-11-09 调研复核):规则表 L1 访问模式理论上可被 Prime+Probe
感知——**理论悬剑**:全生态(KSU/APatch/KP/Magisk)无防御者亦无使用者(ARM
inclusive cache 的 AutoLock 机制使 P+P 在 ARM 上显著更难;反作弊实战仍以 EL0
痕迹/审计/SELinux 指纹为主)。**真实战场在时序信道**(春秋检测器 v4.5.5 实测:
KSU kprobe +188ns 恒偏移被 statx 时延比抓出、KP supercall cmd 范围时延比 >2、
懒分配页探测、0→4KB 用户页额外读取)——对应防线本设计已内置:R1 uid 快速
失败(= KPatch-Next 0.13.5-2 收敛到的按 uid 鉴权同款姿势)、R2 有界拷贝 ≤256B、
R6 透传真行为、句柄制开机一次握手(无逐调用鉴权读用户指针,KP supercall 的
历史漏洞对我们是架构性绕开);KP su gate 自身时延面 = 继承面,归 KP 的猫鼠
游戏。三条实现纪律随协议文档落(P15):①规则表 per-CPU 副本(破坏跨核探测+
表常驻 L1 不产生驱逐信号);②表小型化+访问局部性(压缩信号集);③热路径
零用户指针解引用(除 R2 声明的有界拷贝外——KPatch-Next 最贵学费的直接转写)。

### 6.4 Mm 层观测纯度(present-only 构造保证)

来源:CE(Cheat Engine)源码研究(2026-11-08,memscan.pas)。CE 的
"Active memory only"(`QueryWorkingSet` 快照 → 只扫驻留页,合并连续驻留页为区域)
本是性能优化,恰好构成内存蜜罐的完整防御——读驻留页不触发缺页分配,蜜罐页
(mmap 后从未触碰 = 不在 working set)天然被排除。CE 另有 VQE_PAGEDONLY /
VQE_DIRTYONLY 变体。

KePosed 把它升级为**构造保证而非使用纪律**(RL-17):Mm 读取/搜索默认逐页
`pte_present` 原子谓词(内核页表 walk,只读)——present 才读,不 present 跳过,
**绝不替目标分配页**。与 CE 的差异:CE 用户态"先查后读"有 TOCTOU 窗口,
内核逐页谓词无窗口。zram 换出页同样跳过(不触发解压回填——目标后续访问行为
不变)。需要冷页数据走显式 `MM_READ_FAULTIN` 变体,痕迹决策留给模块作者。

附带红利:PTE dirty 位免费可读——`MmScan` 提供 dirty_only 模式(刚被壳写过/
刚解密的区域天然高亮;CE VQE_DIRTYONLY 同源思想)。

"原理上不可检测"的精确表述(RL-01/17 的理论根据):沙箱 app 的认知渠道只有
自己的 syscall 界面与自己的内存语义;maps/fd/threads/SELinux audit/内存内容——
no-fault 读取一条都不碰。**不可检测不是实现质量的结果,是原语语义的一部分。**
mmap_lock 争用(毫秒级、高噪声、目标自 mmap 罕见)记为可忽略。

### 6.5 ART 内定位:原 dex 而非加壳 dex(机制与知识分离)

定位加壳 app 的原 dex:壳解密后必经 `DexFile::OpenMemory`,ART 在 ClassLinker 的
`dex_caches_` 登记每个 DexFile(`begin_`/`size_`)——壳能抹 dex magic、能擦
string_ids,**但不能抹 ART 自己要用的指针链**(否则 ART 无法懒解析类)。
走链全程跨进程只读,目标进程零痕迹——壳的反 dump 检测盯的所有入口(frida、
maps 读取、断点)我们都不经过。BlackDex/FART/Youpk 走同样的链但全部进程内运行
(可被壳检测);本框架版本从内核走,这是差异化。

**核心架构裁决(RL-18):机制进内核,知识进用户态。** 内核只提供通用原语
(`LdrGetModuleHandle` / `LdrGetProcedureAddress` / `KeFollowPointerChain` /
`MmCopyVirtualMemory`);ART 各版本结构偏移一个字节都不进内核——住在用户态
**locator profile**(JSON:锚点策略 + 每跳偏移,按 Android 版本分发),
新 Android = 更新 profile 数据,内核零重编。

为什么 ART 是白盒有限集:活跃版本仅 7-8 个(Android 8-16);**Project Mainline 后
libart.so 是 APEX 标准件**(Google 统一构建统一分发,OEM 改不了),源码公开——
profile 生成器(tools/,Rust)一份吃全部版本,敌人只有时间,不是机型碎片。

锚点方差(诚实):`Runtime::instance_`(`_ZN3art7Runtime9instance_E`)多数构建在
.dynsym 可查,但 hidden-visibility + LTO 的构建会缺。兜底链:
`JNI_GetCreatedJavaVMs`(JNI 规范强制导出)——不调用它,而是**有界扫它前几条
指令**(adrp/add 引用静态实例的经典模式)反解 JavaVMExt 静态地址,再跳 Runtime。
这就是 profile 里 anchor strategy 字段存在的意义:每版本选一条能用的路,内核只管执行。

探测三层(V1 即终局,2026-11-09 收编:三层全进 v1;层 2 的价值是省 profile 维护):

1. **结构不变量**(零偏移,永不失效):JavaVMExt 布局(vtable + Runtime*,
   4.x 以来未变);DexFile `begin_`/`size_` 后跟 `location_` 指向合法路径字符串
   (自校验锚——读出来不是合法路径 = 偏移错了)
2. **有界指纹探测**(动态查找主体):"指针指向可识别对象"即指纹,每个判据自校验
   ——错偏移只会探测失败,不会静默成功;失败候选立即跳过;首次毫秒级,不在热路径
3. **静态 profile**(AOSP 源码算偏移,clang -fdump-record-layouts 级精度):
   加速+兜底;层 2 探测成功自动回写缓存(同版本 ART 只探测一次)

工程硬点:

- **GC 移动**:链上若经过 mirror 堆对象(GcRoot 指向可移动 DexCache),中途 GC
  会拿悬垂指针——**双走比对**(同链走两遍一致才采信;GC 移动是低频事件)+
  每步大小/对齐/魔法校验,必须是 `KeFollowPointerChain` 内建语义,不指望模块自防
- **壳的用后擦除**:链路终点是"ART 当前持有的 dex"不是"完整 dex"——擦伤部分由
  Exuvia dexdoctor 兜底;且 Ps spawn 事件 + ART 就绪锚点可**抢在擦除前** dump,
  擦除前后各一份,差集 = 壳擦了什么
- **时机**:壳自己要跑 Java 就必须先把 ART 餐桌摆好——app 存活即 ART 就绪,
  壳无法在时间上躲

边界(2026-11-08 深夜修订):此路**通向**方法级 hook 的定位基座——dex
code_item 偏移 + begin_ = 目标进程绝对地址,正是 §6.8 哨兵登记的输入
(方法地址从来不是问题,执行体放哪才是——已由影子页+整模块映像解决)。其余产物不变:
无痕 dump、语义化锚点(给 MmScan/Read)、类/字段元数据读取、配合 Exuvia
组成完整脱壳栈(KePosed = Exuvia 承诺的 ditPro KPM profile 的通用化实现,
Exuvia repair 管线是下游)。微残余:内核读冷页会翻 pagemap 驻留位——
present-only 默认已最小化(§6.4)。

### 6.6 监听接口:脏位监工(2026-11-08 裁决,第一档)

高频读写场景(游戏数值盯防/锁定)的正确形态:**循环本身进内核,模块零轮询**。

```
模块登记: MmWatch(pid, addr, len, [通知|自动改写条件Y→X])
  → 模块登记后保持值班(盯防规则是模块的意志,模块在场 = 执行前提,
    2026-11-09 口径修正:模块不轮询——循环在内核;进程值班至收工 RL-20)
内核监工(定时,最快 1ms 周期):
  每轮只查页表脏位(百纳秒级,不真读内存,不碰目标)
  脏位没亮 → 值没变,什么都不做
  脏位亮了 → 真读一次值,与上次比对:
    确实变了 → (通知模式)经句柄 fd 递给值班中的模块(P14 排队语义实现期定);(自动改写模式)
      命中条件(当前值==Y)→ 驱动直接写 X(锁值——模块登记时声明的意志,
        值班中持续生效;模块进程死 = 登记随之失效,RL-08/20 澄清)
    → 清脏位,继续
```

- **为什么第一档**(:脏位骑墙):查脏位是内核查自己的账本,零接触目标;
  脏位用户态不可读(app 的 soft-dirty 是另一套,互不干扰),清掉无人知晓;
  20 个监听点一轮约 2μs。通知延迟最快 1ms(游戏一帧 16ms,余量两个数量级)。
- **明确放弃第三档**(硬件断点):每线程只有 4 个监视寄存器,占用即暴露
  (目标自己装断点会失败——反作弊专门探这个);实现复杂度爆炸。
  拒绝理由入档。
- **第二档**(写保护陷阱,精确到写入瞬间但侵入目标时间线)**不做**(范围裁决,
  非版本延迟;2026-11-09 复核维持):API 预留精度字段;若启用只允许登记在低频
  写入页(热页上写放大可测)。
- 自动改写 = 监听条目的可选动作字段;"锁定"从每秒写 60 次变为只在游戏真改值时
  写一次。
- 配套保险(桌上件,待逐个裁决):按模块读写配额(防烧光隐蔽预算)、大扫描
  慢速档、调度避让(模块与目标不同核)。批量读参数(一次调用拉 1MB)是
  **第一天需求**而非优化项。

### 6.7 通道定稿:句柄制(2026-11-08 二次裁决,取代 syscall+暗号设计)

**演进史(勿回退)**:初版设计 = 私有 syscall 号 + 每次 128 位暗号验证 → owner 追问
"必须要用调用号吗?" → 复核发现 KSU 2025-11 已完成同款演进(prctl 每次 magic 验证 →
reboot syscall 一次性握手 + anon_inode fd,此后全走 ioctl,#2835)→ **定稿句柄制**。

核心机制:

```
开机一次: keposedd(root)发起握手 syscall(带魔法数)
  → 内核验证 uid==0 + 魔法数 → 分发框架句柄(anon fd,anon_inode:[keposed])
日常:     全部通信 = 对句柄的标准文件操作(read/write/ioctl/poll)
  → 内核 fd 表即凭证:fd 不可猜(非数值密码,内核记账)、不可跨进程偷
    (仅持有者可用)、进程死亡自动失效(close 回调撤销登记,零显式代码)
分发模块句柄: 守护进程 clone 模块子进程(nobody;ns 出生制,RL-07b),句柄经 SCM_RIGHTS
  (Unix 域套接字的标准 fd 传递)递进子进程——绝不经 argv/环境变量
```

被 fd 语义整体消解的旧难题(对照记忆,勿恋战):暗号防猜(常数时间比较)、防偷
(递送通道设计)、防复用(撤销时序)、批量读专用参数(read 天然流式)、事件通知
专用通道(poll/select 天然等待)。旧设计的"128 位 token/标准输入握手包/透传失败
响应"全部作废。

三层检查(取代旧四层,RL-08):查句柄(fd→登记项,一次内核表查询)→ 能力位 →
目标作用域。前两层烙印在句柄登记项里,查询即校验。

选号降级:syscall 入口仅开机用一次。选号从"终生冻结的重大悬案"降级为"挑个不
撞车的"(避开 169=KSU/45=KP;启动探测照旧——应答异常即拒绝启动,宁死不撞车)。
生态占用调研(KSU-Next/susfs/魔改内核)从"拍板前置条件"降级为"发布前检查项"。

诚实风险(首批真机必验):①严格 SELinux 策略下 nobody 进程对 fd 执行 ioctl 是否
放行(预期放行——fd 操作的 SELinux 检查挂在 open 时,不在 ioctl;但必须实测);
②fd 泄漏面:模块进程的 /proc/<pid>/fd 对同 uid 可见——nobody 互见无妨(拿到 fd
数字≠拿到 fd;fd 不可跨进程按数字引用)。

### 6.8 方法级 hook 终局形态(2026-11-08 定稿:影子页双视图+读透明;2026-11-09 重构:整模块映像跳板)

**演进史(勿回退)**:初版裁决"方法级 hook 明确不做,引导到 LSPosed"(基于
"hook 执行体必须驻留进程内"的隐含假设)→ owner 两次追问("我们就在 art 里"/
"内核重定向到模块的导出函数?")→ 重新穷举设计空间 → 发现异常驱动 + 视图切换
可以实现**零驻留的方法级 hook** → **推翻旧裁决,v1 一次性实现终局形态**
(RL-23;不分期的理由:地基共用,分期=重做)。
**第二轮重构(2026-11-09,多轮商讨定稿,勿回退)**:原"页面搬运"参数错误——
**搬一页**只带 .text,全局量/GOT/TLS 全不在场,作者被迫写零依赖裸函数(开发
体验死亡)→ owner 定调三条件(**不注入、支持高热函数、开发体验友好**;
"将模块搬到内存直接使用导出函数都可以"——导出与否是实现细节)→ upcall
复活提案(暂停-寄现场-回决定)**二次否决**(owner:"不行……我需要支持热
方法";50-200μs 挂起语义,热路径不可用)→ 定稿**整模块映像**:映像 = 模块
自己的内存(不是内核快照——owner 明确纠正;不是目标的——映像始终属于模块
进程),注册时驱动把映像页**订住**(lock,不换出),窗口期驱动让目标线程
"用上"这几页。**执行手段 = 驱动的活,设计不锁死**(临时挂页表/翻译/其他,
owner 原话:"不应该是替换,也可以是翻译等不同手段(我没想好),总之那是
驱动的活");**验收线 = 目标任何视角永不可见**(读该范围 = 正常"无映射"
报错;maps/任何清单 = 无记录;窗口开多久都一样)——手段必须天生过线,而非
事后遮蔽。窗口时长**不设限**(owner:"如果是故意的,就不是我们的问题,我
本来的含义就是故意延时,但不是恶意延时"——超时强拆机制整体删除)。模块
死亡处理:驱动经句柄 close 回调自动知晓(内核事件,快于任何轮询),摘掉
哨兵;**在飞窗口自然跑完**(映像页订着,执行不受影响),后续调用走原方法;
daemon 职责 = 控制面善后(日志展示/按策略决定重拉)。

**设计空间四象限(已闭合,不存在第五种)**——"hook 逻辑住在哪"的全部可能:

| 象限 | 机制 | 单次成本 | 判决 |
|---|---|---|---|
| 内核数据 | 脏位监工数据钉死(§6.6) | ~0 | v1(已定) |
| 内核代码 | 异常陷入→内核改寄存器→弹回(路 D) | 1-3μs | 终局方案的地基/验证台阶 |
| 模块代码在**目标**跑 | 整模块映像:窗口期驱动让目标线程执行模块映像(2026-11-09 重构;原"单页搬运"作废) | 2-5μs 无挂起 | **终局方案的跳板设计** |
| 模块代码在**自家**跑 | upcall:挂起目标等模块应答(FUSE 模式) | 50-200μs + 挂起/死锁 | 已淘汰;2026-11-09 复活提案**二次否决**(owner:热方法不可用,维持淘汰) |

**终局方案全链**(每次方法调用):

```
平时(99.999% 时间): 方法页 = 原字节。读/校验/扫描/哈希——全部原样。
  零暴露窗口(视图切换只发生在"执行取指"的硬件事件上)。

执行瞬间:
  ① 目标线程取指方法 M 的地址 → 该页权限位(执行触发异常)→ 陷入内核 ~1μs
  ② 内核查"哨兵哈希表"(地址→影子页,~100ns):
     不是哨兵地址(同页邻居方法)→ 立即放行原页(邻居只付一次快速失败,
       时序模型同 Zw 层 R1,§6.3)
     是 → ③ 把该虚拟地址临时指向影子副本(复用原页虚拟地址,maps 零变化),
          改 PC 重取指,返回用户态
  ④ 线程在影子页全速执行:开头 = 跳板(保存现场 → 驱动让目标线程"用上"
     模块映像(整模块:代码+全局数据完整着装——回调里全局量/静态库纯计算
     函数随便用,LSPosed 级开发体验;手段 = 挂载/翻译等,实现期定)
     → 进入模块回调函数 → 恢复/改写现场 → 返回哨兵)
  ⑤ 哨兵再次陷入 → 驱动拆除映像的临时可达,页表还原
     → 线程回到方法 M 之后,毫无感知

读透明(对抗哈希校验的关键,GeptHooks HideRead 同思想):
  影子页 exec-only(执行不许读)——窗口内若 app 读/校验该 4KB → 触发陷入
  → 内核这次给它看**原字节** → 校验永远通过。
  "看"与"执行"是两个世界——这是整个方案的检测免疫核心。

映像不可见(验收线,对映像范围同样成立):
  目标对映像范围的任何观测(读/maps/任何清单)= "不存在";
  手段(挂载时遮蔽/翻译天生不可见)= 实现期定,验收线不因手段妥协。
```

**使用成本**(体验/稳定/安全三把尺,owner 项目级原则):
- 热方法:每次 2-5μs(异常 ~1μs + 映像可达切换;高热函数扛得住——这是
  upcall 被否、本方案被定的物理理由);低频方法无感
- 内存:每 hook 页 = 影子副本 4KB + 哨兵表项(可忽略);模块映像页被订住
  (不换出)——按模块设映像配额(实现期待办,桌上件)
- 稳定性:异常路径只做"查表+换页表项"(最少活动部件;不碰寄存器手术/单步舞蹈)
- 安全:读透明封死哈希校验;maps 零变化;原页字节永不改动(RL-23①);
  映像永不可见(验收线)

**工程硬点(实现期逐项解决,均有标准解)**:多线程同页并发命中(内核串行处理)、
指令缓存冲刷(ARM64 改映射后 invalidate icache,否则执行旧指令)、模块函数在
目标进程内崩溃的异常归属(**如实入档:回调写崩,崩的是目标进程**——代码跑在
目标线程上,此为该路线固有属性,同 LSPosed)、exec-only quirk 启动探测
(P4 已缩水:探测+兜底,不再是设计决策)、TLB 一致性跨核传播、映像"订页"
的具体机制与窗口期可达切换手段(驱动的活,验收线已定)。
多模块同址冲突语义(P11,2026-11-09 裁决):哨兵/T0 规则/MmWatch 同址重复
登记一律 `-EBUSY`,**拒绝共存**——地址→单张影子页,无链概念,不做 hook 链。

**与其他能力的组合**:ART 方法级定位(§6.5)提供方法地址 → 哨兵登记;
数据钉死(§6.6)覆盖数据驱动逻辑(更便宜);方法级 hook 覆盖控制流逻辑——
三层能力互补(与 LSPosed 的关系同样是互补:进程内生态兼容 vs 进程外无痕,
同一目标的不同方法,口径见 §1)。

**目标形态覆盖(2026-11-08 追加入档,owner 确认)**:

| 目标形态 | 取指位置 | 双视图有效? | 应对 |
|---|---|---|---|
| AOT 编译(oat 代码) | oat 代码页,映射稳定 | ✅ 一级目标 | 直接挂哨兵 |
| JIT 编译(热点方法) | JIT 代码缓存页 | ✅ 但代码会搬家 | 脏位监工盯 ArtMethod 入口字段,变了=重编译/搬家=哨兵重挂(§6.6 咬合,零新机制) |
| 解释执行(冷方法) | libart 解释器把字节码**当数据读** | ❌ 页只被读不被执行,读透明喂原字节=hook 落空 | 同上:方法变热被 JIT 编译那一刻监工落哨兵。残余:极冷方法永不被编译=永挂不上(LSPosed 反而能 hook 解释方法,诚实记录);注册到编译之间有空窗 |
| 被内联(方法体拷进调用者) | 调用者代码页 | ❌ 无调用边界 | **全行业无解**(LSPosed 同样被穿透);实践中 hook 目标(多态/跨模块热点)编译器不敢内联,碰撞率低 |
| **native 函数(.so/oat 内 C++)** | native 代码页,**地址固定不搬** | ✅ **最佳目标** | 加固壳延迟解密的页:监工盯页脏位,解密发生=影子页重建(已有机制)。调用全覆盖:任何调用路径(同库直调/虚表/PLT)取指必过哨兵——PLT hook 只拦跨库调用漏掉同库直调,双视图无此洞 |
| **直接运行的原生可执行文件(非 app)** | 主程序 .text,静态映射**永不搬** | ✅ **最干净目标** | 引擎零新增(hook 是页面级、进程无关——哨兵不区分代码属于谁);无 JIT/无移动/无解释内联缺口;spawn 信号最直接(必经 execve);ART locator 整层不需要;静态链接无导出 → MmScan 自救(P2:模块的事)。作用域以可执行路径标识(RL-04a 扩展,2026-11-09) |

native 覆盖的意义(与 LSPosed 互补口径):游戏整块市场(Unity il2cpp/Unreal/
热更框架)逻辑几乎全 native,LSPosed 框架层面不涉此域(其模块自救方案是自带
inline-hook 库:改字节/驻留跳板/自哈希必炸——加固与反作弊检测正是冲它们设计的);
双视图三件套(hook+Mm 读写+监工)对此域完整覆盖且检测免疫。**这是互补生态位
的差异化能力,不是对 LSPosed 的替代**——LSPosed 的强项(Java 生态兼容、
海量现成模块)依然成立。

**hook 两形态(平权,2026-11-08 定稿;2026-11-09 T2 重构 + owner 平权裁决:原"能力阶梯"一词作废——T0/T2 非等级关系,是模块意志的两种等价形态,v1 完全体 = 两者并列)**:

**平权注记(2026-11-09 owner 裁决)**:简单规则与复杂回调**同一等级、同一地位**——
T0 是模块意志的**数据形态**,T2 是同一意志的**代码形态**;形态不同,归属相同。
简单规则"从代码层面看确实更简单"只是**驱动执行工作量更小**,绝不构成"驱动替
模块决策"——驱动对两者的关系完全一样:**忠实执行登记内容,不判断、不补全、
不升华**。"简单到驱动可以自己看着办" 是错觉,是决策权走私的入口,禁止。
**复合与不可分割(同日 owner 定锚)**:旧表述("零用户态参与"+在岗要求)与修正版
**行为一致,本体不同**——旧表述是"驱动自主执行"与"模块强制在场"两件事的**复合**
(在场 = 外挂约束,原理上可谈判——这正是快照类设计 hooklet 的思想母体);修正版
**原理上不可分割**:登记即模块意志本身,意志不能没有意志者。由此"模块死亡 →
登记失效"不是被强制执行的策略,而是**逻辑必然**(同义反复)——RL-08 的 close
回调只是该必然性的实现机制,不是策略检查。复合表述下快照类设计是"被禁止";
原理表述下它们**先天矛盾,无从提出**——差别不在行为,在设计空间的封死方式。

| 形态 | 机制 | 模块进程 | 状态 |
|---|---|---|---|
| **T0 静态规则(数据形态)** | 注册时递静态规则(跳过返回 X/改参放行/条件放行),内核往影子页写固定指令(mov x0,#X; ret 一类)——零链接器 | 在岗(规则是模块的意志,RL-20 澄清) | **v1**(路 D 地基复用,近零成本;卡密"激活一次永久生效"主场景) |

**跳板函数语义模型(2026-11-08 深夜商讨定稿;2026-11-09 契约部分随整模块映像重构改写)**:

1. **形态 = LSPosed 回调的镜像**:模块注册时递函数地址(导出与否 = 实现细节,
   owner:"仅需要调用 api 即可 hook"——无导出仪式要求);目标线程在窗口期
   经映像直接执行模块回调。函数收 `Context` 结构(完整寄存器现场 + Java
   方法实参 x0-x7 + 方法元数据——类名/方法名/签名,ART locator 免费附送)。
   返回值三选一:**PASS**(原样放行)/ **FABRICATE**(原方法照跑,返回值
   被我改)/ **SKIP**(原方法不跑,替它返回)。
   回调里全局变量/静态库纯计算函数正常可用(映像是模块自己的内存——这是
   "整模块"相对"单页"的全部意义)。
2. **跳板内部调用框架 API(LSPosed 同构)**——"一条协议,两种运输":

   ```
   模块进程(自家宇宙):  ioctl(句柄fd, cmd, ...)      ──┐
                                                          ├→ 同一套命令分发
   跳板内(目标宇宙):    UDF 魔数陷阱 + cmd 寄存器      ──┘  (鉴权不同,命令同号)
   ```

   跳板内无 fd,凭证 = 执行位置本身(内核记录"此线程在模块 X 的 hook 窗口",
   API 陷阱调用自动归属模块 X,照走作用域检查)。UDF 陷阱不走 syscall——
   不进 syscall 跟踪、不过 seccomp,比 syscall 隐蔽。API 面:
   `invoke_original`(调原方法——必须走内核,原方法页是哨兵页,直接调
   触发自己死循环;内核临时恢复原视图执行)、`resolve_method/field`
   (= XposedHelpers.findClass/findField,ART locator)、`read/write_remote`
   (跨进程,LSPosed 无此能力——直接寻址做不到跨地址宇宙,API 反而更强)、
   `log`(走框架日志,绝不能走目标的 logcat)。
3. **直接访问规则(裁决)**:跳板内对**当前目标**的普通指针解引用 = 允许
   (对等 LSPosed 模块在进程内的自由;owner:"如果 LSPosed 模块本身就允许
   这样做,我们也允许直接访问")。作用域外访问:读写都是驱动代劳,
   **逐次拦截**(裁决:作用域强制贯穿每一次内存访问,不是门口查一次)。
4. **框架义务**(保证模块"本来能做的都能做"):哨兵重入计数(hook 内调用
   目标函数再触发哨兵不死循环)、跳板 ABI 递交完整现场、栈深度文档化
   (v1 跑目标线程自己的栈,同 LSPosed;独立备用栈 = 实现期研究项,
   Linux use_temporary_mm 先例)。
5. **命名**:命令族命名**搁置**(P3,owner:"文字而已,后期商讨");已否
   候选:Hk 族;文档一律"待命名"占位,不阻塞设计。

## 7. Gateway 协议规范(通道层)

- **通道形态(句柄制定稿,RL-22/§6.7)**:开机一次 syscall 握手(带魔法数,
  root 发起;nr 避开 169=KSU/45=KP,启动探测应答异常 = 拒绝启动)→ 框架句柄
  (anon fd)→ 之后全部通信走 read/write/ioctl/poll,帧:`{u16 proto_ver, u16 cmd,
  ...}`(帧里显式带协议版本,RL-11)。syscall 入口仅此一次,低频透传无时序面。
- **守护进程通道(裁决)**:daemon 持框架句柄,管理命令(Ob 族)直接对句柄
  ioctl——鉴权在握手时一次完成(uid==0),之后 fd 即身份。
- **模块句柄(裁决)**:注册时内核铸造(烙印能力位+作用域),守护进程 clone 出生制
  (RL-07b)时经
  SCM_RIGHTS 递进子进程;模块对句柄的每次操作过三层检查(RL-08)。
- **事件通道(裁决)**:内核→守护进程**点对点**(守护进程是唯一受信订阅者,
  内核不认识模块);守护进程→模块按生命周期模型(§4 数据流/RL-20/21)——
  事件型拉起时事件写进标准输入;同模块节流(在跑不重复拉,事件排队)。
- **能力位**:`uapi/capability.h` 定义(mem_read/mem_write/mem_search/syscall_shape/
  process_events …)。能力粒度到**原语族**,不做参数级能力(过度设计)。
- **错误码约定**:`-EACCES` 模块越权;`-EPERM` 框架级拒绝(安全模式);`-EBUSY`
  同址重复登记(P11,拒绝共存);`-EPROTO`
  协议版本不匹配;`-EOPNOTSUPP` 命令不存在/已废弃;`-ESRCH` 目标进程不存在;
  `-EFAULT` 用户指针无效。语义表是协议规范的一部分,变更需同步文档。

## 8. 验证协议

- **构建**:KPM 在 KernelPatch 检出环境内构建(镜像 `kpms/demo-hello/Makefile`),
  工具链 `aarch64-none-elf-`;产物 `keposed.kpm`。daemon 用 NDK 静态构建。
- **构建环境与分工(owner 裁决,2026-11-08)**:owner 开发机是 **Windows**——Linux
  侧构建(KPM 交叉编译等)由协作 Agent 在 Linux 沙箱承担(`aarch64-none-elf-gcc` +
  KP 检出环境即可;KP 自己的 CI 用 `ghcr.io/ylarod/ddk-min` 容器构建 DDK 产物,
  KPM 构建更轻,无需 DDK)。daemon 是 Rust,可 **Windows 原生交叉编译**
  (`cargo build --target aarch64-linux-android`);WebUI/Node 平台无关。日常迭代:
  Rust 逻辑在 Windows 写测(单测可跑 Windows),KPM 改动才进 Linux——接触面很小。
  仓库可选 `.devcontainer` 固化贡献者环境(参考 owner 的 ScreenshotFaker 实践)。
- **CI 边界(诚实)**:CI 只能做协议一致性检查——UAPI 头与 `docs/native-api.md`
  的命令码/结构体/错误码三向同步校验(脚本比对),外加 daemon/模块模板的构建。
  **内核代码无法在 CI 验证**;每个触碰 kpm/ 的 PR 必须在 PR 描述里写明:
  测试设备、内核版本、加载器及版本、KPM_EXIT 后设备是否存活。
- **真机判据序列**(每次 kpm/ 改动后全过,人类执行):
  1. 加载:dmesg 横幅版本号与源码 `KEPOSED_BUILD_TAG` 一致(防旧二进制上机);
  2. gateway:module-template 全原语跑通(attach→read→search→write→detach,
     每步校验读回一致);
  3. 塑形:Zw 层安装 openat 塑形 → 目标进程读路径拿到塑形结果 → 卸载后恢复原生;
  4. 越权:砍掉模块 write 能力位 → write 返回 `-EACCES`(鉴权在参数解析前的证明);
  5. 生命周期:卸载框架 KSU 模块 → 模块进程死、句柄失效(重放 ioctl 全部失败)、
     KPM 干净卸载、设备存活。
- **崩溃取证**:KPM panic → 保留 pstore/dmesg,对照 §2 逐条归类;修复必须回写
  判例到本文档(这是本文档的活契约属性)。

| 透传 | (句柄制下仅存于握手号)非暗号/非握手的 syscall 流量原样转真 handler,与原厂行为一致——入口号探测无差异 |

| 读透明 | 影子页 exec-only:窗口内的读/校验访问触发陷入,内核透出原字节——哈希校验永远通过(GeptHooks HideRead 同思想) |
| 页面搬运 | 已修正词条(2026-11-09):原"临时映射模块导出函数单页"形态作废(单页带不动依赖闭包,作者被迫写裸函数)——T2 现为**整模块映像**(见该词条);保留词条名防混淆 |
| 整模块映像 | T2 跳板载体(2026-11-09 定稿):映像 = 模块自己的内存(代码+全局数据,始终属于模块进程),注册时驱动把映像页订住(lock 不换出);窗口期驱动让目标线程"用上"这几页——具体手段(挂载/翻译等)= 驱动的活,实现期定;**验收线 = 目标任何视角永不可见**(读=无映射报错,maps=无记录,窗口开多久都一样) |

| 哨兵哈希表 | 内核内"地址→影子页"快查表;非哨兵地址(同页邻居)立即放行原页 |
| 四象限设计空间 | "hook 逻辑住哪"的全部可能:内核数据/内核代码/模块代码目标跑/模块代码自家跑——已闭合,不存在第五种(§6.8) |

## 11. 给接手 Agent 的行为准则

1. **动手前**:读完本文档;对照 §3 确认你要做的事不在"反直觉裁决"里;
   涉及内核代码的,逐条过 §2 的 RL 清单。
2. **写协议时**:任何 UAPI 变更 = 头文件 + `docs/native-api.md` + 协议版本号三处
   同一 commit(RL-11);先想清楚再动——无 SDK 生态里 ABI 错误没有回滚窗口。
3. **写内核代码时**:预分配优先于运行时分配;`KPM_EXIT` 与安装对称;每条 hook 都有
   unhook;页表写只走 `mm/` 的唯一实现(RL-05)。
4. **想加东西时**:先问"这是执行原语还是决策逻辑"——决策逻辑进模块,不进内核;
   再问"这会不会在目标进程留下任何痕迹"——会,则拒绝(RL-01/02)。
5. **想"优化"时**:对照 §3。如果你觉得某条原则"明显更好",大概率它已经在那里被
   推翻过一次;仍确信,带着论据找人类维护者。
6. **诚实性**:没上机验证过的不写"已验证";计划中的能力不写成已实现;
   PR 描述里的测试记录按 §8 判据序列逐项填写。
7. **交付给下一个 Agent 时**:更新本文档的"当前状态"(§0),像 handoff 一样诚实记录
   做了什么、什么没做完、为什么。
8. **语言矩阵是裁决不是偏好**:KPM=C(KP 工具链锁死,freestanding 无 libstdc++,
   Rust no_std 重实现 KPM ABI = 纯负担);daemon=Rust(ksud 先例 + bindgen 消费
   uapi 单一事实源);WebUI=TypeScript(克制,vanilla/Preact);拒绝 Go/Kotlin/JVM
   (root 守护进程拖 ART 运行时)。勿引入第四种核心语言。
9. **构建分工**:Linux 侧构建由你在沙箱承担(owner 开发机 Windows);daemon 的
   Rust 改动可建议 owner 在 Windows 原生交叉编译自测;KPM 产物由你构建并附
   校验和。约定见 §8。
10. **模板与 uapi 的许可证陷阱**:module-template 双模板文件头单独 Apache-2.0
    (RL-15)——模板带 GPL 头 = 闭源模块作者复制模板第一步即被传染;新增模板
    文件时逐文件检查 SPDX 行。
11. **商讨纪律(2026-11-08 教训入档)**:owner 的话分"裁决"与"思考/商量"两种,
    **默认是后者**——不得把商讨中的话自动升格为定案,不得用"定了/定稿/清空清单"
    等词汇催促收敛;每轮结尾明确标注哪些是新裁决、哪些仍在桌上;重大决定
    (如选号)即使 Agent 认为证据充分,**拍板权永久在 owner**。急着完成
    ≠ 帮 owner。
12. **方法级 hook 纪律(RL-23/§6.8)**:实现只认终局形态(影子页+读透明+整模块
    映像);四象限设计空间已闭合,**勿重新开放"hook 逻辑住哪"的讨论**——将来
    的更好方案是替换跳板策略,不是新象限。upcall 已淘汰,勿复活(除非 owner
    主动重开)。§9 待商讨清单未拍板项(当前 P3、P13;其余已闭合或归实现期)在协议文档相应章节标注悬置。
13. **V1 即终局(2026-11-09 元裁决)**:不存在 V2——评审与实现建议中禁止"下一版
    再说/将来再优化":能力要么进 v1、要么明确砍掉并记录理由。文中残留分期措辞
    发现一处修一处(修法 = 收编进 v1,或改为"范围裁决:不做,理由…")。
